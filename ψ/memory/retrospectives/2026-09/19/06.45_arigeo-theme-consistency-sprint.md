## Lessons Learned

- **Pattern**: When a CI/CD job wraps a long-running remote operation (a deploy CLI, a cloud build), a job-level timeout killing the *orchestrating* process does not prove the *remote* operation also failed — verify the remote system's own state via its API before concluding failure or retrying.
- **Pattern**: Before applying any bulk mechanical substitution across many files (color tokens, renamed identifiers, etc.), generate a full dry-run report and review it for edge cases first — it's far cheaper to catch a misclassification in a report than after it's already been written to 6 files and needs to be discovered via a visual regression.
- **Discovery**: A sibling repo's already-shipped, already-approved design decision (arigeo-hr's light/dark brand-red pair) is a legitimate, low-risk source to reuse when a related repo faces the same problem for the first time — don't re-derive a brand color decision from scratch when a family precedent already exists.
- **Mistake**: Don't run `git commit --amend` immediately after a `git add` staged files for a *different* intended commit — it silently merges them. Check `git status`/`git diff --cached` right before any amend, not just before the original commit.
