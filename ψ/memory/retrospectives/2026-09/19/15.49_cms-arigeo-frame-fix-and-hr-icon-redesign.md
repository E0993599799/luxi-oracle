### Architecture Decisions

1. **Diagnose via live `getComputedStyle`/`document.styleSheets` inspection in a real connected browser, not source-reading alone**, for the cms-arigeo frame bug — the earlier PR #124 audit had already proven that source-reading can miss cascade-order bugs; this session had, for the first time, an actual authenticated browser connection to use instead of guessing.
2. **Verify a deterministic CSS-removal fix via compiled build output when a live preview click-through is unavailable** (cms-arigeo's preview deployments 500 on login cross-origin) — a real, repo-specific limitation distinct from (but related to) the already-known ZITADEL-SSO-blocks-local-verification issue.
3. **Recreate the reference icon PNG as hand-authored SVG shapes, not a raster vectorization trace** — a vectorized trace of a raster image produces messy, oversized paths; redrawing as simple flat shapes in the same color language is smaller, crisper at icon size, and matches how the existing icon system was already built.
4. **Keep icons as inline React SVG components, not static asset files**, even though the new set is visually heavier than the old one — preserves the zero-extra-network-request property that made the old single-color set fast, directly serving the "don't load slowly" requirement.

2. **Local static server for icon preview unreachable.** Symptom: `python3 -m http.server` on the sandbox, then navigating the connected browser to `localhost:8934`, produced an empty/blank tab. Cause: the connected browser runs on พี่เอก's own Windows machine, not the sandbox — `localhost` there is a different machine entirely. Resolution: navigated to a real HTTPS origin (`example.com`) first, then rewrote the page via chunked `javascript_exec` DOM injection to render the icons.
3. **`data:` URL navigation blocked.** Symptom: `navigate` to a `data:text/html;...` URL returned "Can't interact with browser-internal or unparseable URLs." Resolution: same workaround as above (real origin + JS injection) rather than fighting the URL scheme restriction.

## Lessons Learned

- **Pattern**: When a page's computed background/color doesn't match its CSS custom properties despite the right `data-theme`/class being set, inspect `document.styleSheets` for a second, later-loaded rule targeting the same selector before assuming the token system itself is broken — same-specificity, later-source-order duplicates are a common leftover from an incomplete refactor, not a sign the new system doesn't work.
- **Pattern**: When a static asset preview isn't directly reachable (wrong machine, blocked URL scheme), navigate to any real HTTPS origin first, then inject content via chunked script execution — this sidesteps both "unreachable localhost" and "blocked `data:` URL" failure modes in one move.
- **Mistake**: Don't let a documentation habit (writing a `ψ/` vault file per shipped PR) silently lapse just because an alternate persistence path (an MCP memory tool) is also available and feels "good enough" in the moment — check that both actually happened, or explicitly decide to drop one, rather than letting the pattern erode without noticing.
- **Discovery**: A repo's `vercel.json` absence (vs. an explicit `"git": {"deploymentEnabled": false}` override, as cms-arigeo has) is a reliable, checkable signal that standard git-push auto-deploy is active — worth checking before assuming a manual build/deploy dispatch is needed on any new-to-this-session repo.
