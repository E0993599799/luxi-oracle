## Honest Feedback

Three friction points, all specific to this short tail: (1) Re-invoking the full default `/rrr`
flow — including spawning a second background timestamp-miner subagent — for a segment this small
is disproportionate process overhead; the subagent round-trip (spawn, wait for notification, parse
output) took longer than the actual retro-writing work it fed into. (2) The session's `.jsonl`
treats a ~10h39m wall-clock span with two multi-hour silent gaps as one undifferentiated file,
which meant I had to manually reconstruct which timestamps were "session start," "still working,"
and "picked back up hours later" from raw message deltas rather than the data being pre-segmented
— easy to get wrong if I hadn't cross-checked the actual gap sizes before writing the header.
(3) The `/rrr` skill's own instructions get re-loaded in full (several thousand words) on every
invocation via the `<command-message>` envelope, which is a lot of fixed overhead relative to an
11-minute, 6-message tail segment — not something I can control, but worth naming as a real cost
of the pattern.

## Lessons Learned

- When a session's raw timestamp log shows multi-hour gaps between messages, treat those as real
  session-boundary markers in any retrospective or timeline — state the gap explicitly rather than
  reporting wall-clock duration as if it were continuous active work. A reader trusts a duration
  number at face value; an unstated multi-hour gap inside it is a quiet inaccuracy.
- Match the weight of a memory artifact to the weight of what it's tracking: a full
  frontmatter'd, "how to apply"-documented memory file is right for a durable, reusable pattern,
  but a one-off, self-expiring reminder ("check X next time") is often better served by a lighter
  mechanism (a Next Steps line, a single terse note) — don't reach for the heaviest available tool
  by default just because the skill documents it most thoroughly.
- Before running a full default retro flow (background subagent + multi-section template) on a
  short tail segment, weigh whether `--quick` mode would capture the same substance with less
  fixed overhead — the choice of retro mode should track the size of what happened, not just
  "which mode was invoked last time."
