## Lessons Learned

- When a cloud routine's prompt tells the agent to run a script that lives in a specific repo,
  verify that repo is actually listed in the routine's `sources` array before considering the
  routine done — writing the instruction in the prompt does not make the checkout exist. Check
  it explicitly, don't infer it from having *discussed* the dependency.
- Before treating a red CI check on a PR as a regression caused by that PR, diff the failure
  against the base branch's own recent CI history (e.g. `gh run list --branch main --workflow X`)
  — a pre-existing broken test on `main` will fail identically on every PR built from it,
  independent of that PR's actual diff.
- When an API for managing remote/cloud resources has no documented field for injecting secrets,
  don't try to route the secret value through some other available channel (env file read + tool
  call) just because it's technically possible — the missing field is usually a deliberate
  boundary (secrets belong in a dedicated UI, not an assistant's tool-call context), not a gap to
  engineer around.
