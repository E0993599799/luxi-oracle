### Key Code Changes

- **`gen_svgs.py` `svg_wrap()`**: viewBox height didn't include the title's `y0` translate offset, silently clipping the bottom of every diagram (~4px on the simple flow, ~36px on the 4-branch CMS-role diagram). Fixed: `h = content_h + y0`.
- **`build.py` print CSS**: removed `h2 { break-before: page }` (forced every section onto a fresh page, inflating page count ~45% with near-empty pages) in favor of `break-after: avoid` on all headings (natural flow, orphan-safe, denser).
- **`build.py` `wrap_table_thead()`**: restructures every `<table>` into real `<thead>`/`<tbody>` so the header row repeats when a table spans a page break (a bare first `<tr>` does not auto-repeat).
- **`build.py` print CSS**: `img { max-height: 200mm }` — a screenshot taller than ~one page was breaking Chrome's ability to honor `break-after:avoid` on the heading before it.

### Architecture Decisions

- **v1.0/v1.1 kept as separate files, not overwritten** — per Luxi's "Nothing is Deleted" principle; README marks v1.0 rows "superseded by v1.1 below" rather than deleting them.
- **Diagrams redrawn as inline SVG from verified manual text, not regenerated via the just-learned Pretty-mermaid-skills tool** — that tool needs the original Mermaid DSL source, which the pack didn't include; reconstructing from the manual's own role tables/step lists was higher-confidence than guessing at tofu'd image content.
- **PDF QA switched from pdfjs-dist+`canvas` to `mupdf` (WASM)** — the former silently dropped all embedded custom-font text on ~30% of pages and crashed on radial-gradient fills; `mupdf` rendered every page correctly with no native-binding fragility.

## Lessons Learned

- **Pattern**: A print-CSS PDF's pagination cannot be verified from a live-HTML screenshot — it only exists once the print fragmentation pass runs. Rasterize the *actual PDF*, page by page, as the first verification step, not the last resort after a user complaint. (see `[[2026-09-14_print-pdf-pagination-rules]]`)
- **Mistake**: A session-start repo/branch check applies per-repo, not once per session. Touching a second repository hours into a session without re-running `git branch --show-current` there is the same failure class the Session Start Protocol exists to prevent — it doesn't matter that the check was already run once on a different repo.
- **Discovery**: `pdfjs-dist` + `canvas`/`@napi-rs/canvas` is not trustworthy for QA-rendering a PDF with embedded custom-subset fonts or CSS gradients — it silently drops text and crashes on shading patterns. `mupdf` (npm, WASM-based) renders the same PDFs correctly with no native-binding setup pain.
- **Discovery**: When a `git checkout` to another branch is refused because a repo's working tree is full of unrelated third-party uncommitted state, `git worktree add <tmp-path> <branch>` gives a fully isolated checkout for cherry-picks/merges without ever touching that state or requiring a stash.
