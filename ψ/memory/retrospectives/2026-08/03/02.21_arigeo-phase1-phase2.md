## Lessons Learned

**1. Bundle Size Metrics ≠ Shipped Size**
In Next.js/Vercel deployments, `node_modules` size is misleading for production assessment. The relevant metric is `.next/` output size and runtime bundle (what ships to users). Learned to distinguish: 464MB node_modules (development) → 373MB production-only → 2.8MB shipped. Future audits will measure shipped size, not installed size.

**2. i18n Context Requires Server-Side Components**
next-intl provides context through server-side layout providers. "use client" components can't access this context directly. Solution: either keep translation calls server-side, or pass translations as props from server parents. This is a design constraint, not a bug—once understood, shapes all i18n component architecture.

**3. Half-Measure Deployments Confuse Status**
Shipping partial implementation (Thai infrastructure without content) creates ambiguity. Users see "Thai page loads" (true) and "Thai text displays" (false). Clearer to either (a) ship infrastructure + documentation, or (b) wait for full content before shipping. Mixing causes status confusion.

**4. Deployment Feedback Loops Need Local Parity**
Tested via Vercel build → wait → verify cycle. Each iteration burned 30-45s. Local `npm run build` + browser testing would have compressed this dramatically. For next major feature, set up local dev early to avoid remote-build dependencies.

## Blockers & Resolutions

**Blocker 1: Build error on not-found page**
- Error: "useLocale() called outside i18n context on /_not-found/page"
- Root: Header/Footer components use `useLocale()` but were in root layout (no locale context)
- Resolution: Moved Header/Footer to `[locale]/layout.tsx`, created separate `not-found.tsx` at root
- Learning: Locale-dependent components must render within locale segments

**Blocker 2: Client-side error after Thai integration**
- Error: "Application error: a client-side exception has occurred"
- Root: HomeIntroStatement and BrandCarouselSection had `"use client"` but called `useTranslations()`
- Resolution: Removed `"use client"` directive, rendered as server components
- Learning: useTranslations() requires server-side context; can't be "use client"

**Blocker 3: Vercel deployment authorization required**
- Error: OAuth flow needed to interact with Vercel via MCP
- Root: Authentication was not persisted from previous session
- Resolution: Re-authenticated via OAuth callback URL
- Learning: Vercel CLI auth is session-scoped; need to re-auth if session changes
