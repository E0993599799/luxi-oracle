## Lessons Learned

### 1. Git Safety Check is Non-Negotiable
**Rule**: Always run `git fetch origin && git diff origin/HEAD...HEAD --name-only` before pushing, even if `git status` says "up to date." Local tracking can lag. This prevents silent overwrites of teammate pushes.

**Why this matters**: "up to date with origin/branch" only checks your tracking branch, not actual remote state. Real remote is the authority.

**Actionable**: Add pre-push habit: `git fetch` → check remote divergence → then `git push`.

---

### 2. Cubic-Bezier Easing for Smooth Motion
**Rule**: Use `cubic-bezier(0.22, 1, 0.36, 1)` (or similar acceleration curves) instead of linear `ease` for UI animations. Feels more alive, less mechanical.

**Why this matters**: Easing function choice determines motion *personality*. Linear easing (default `ease`) feels corporate/robotic. Cubic-bezier with early acceleration + late deceleration feels organic (matches human motion).

**Actionable**: For any animation >200ms, pick an easing curve intentionally. Don't default to `ease`.

---

### 3. Icon Size Should Scale Proportionally with Container
**Rule**: When resizing a button/icon pair, scale both proportionally. If button grows 27% (44→56px), grow icon ~55% (18→28px) to maintain visual weight ratio.

**Why this matters**: Icons that don't scale with containers look cramped or lost. Proportional scaling maintains visual balance.

**Actionable**: Before resizing, calculate target ratio: (icon size / container size). Keep ratio ~0.5 for icons in buttons.

---

### 4. Broadcast Events Mark Context Boundaries
**Rule**: When switching between oracles' repositories (multi-repo session), emit a fleet broadcast event. Format: "Oracle: <from> → <to> | reason".

**Why this matters**: Other oracles in the fleet can track where you are, understand task flow, and detect context switches that might cause bugs.

**Actionable**: Add emit before `cd` into different oracle's repo.

---

### 5. Ask Before Expanding Scope (Even Exploratory)
**Rule**: If you spot a bigger issue than requested, acknowledge it, ask permission to explore, don't just do it. Respect user's scope.

**Why this matters**: Self-directed scope creep burns tokens and context. User might have tighter deadlines than you assume. Permission-first approach = collaborative, not dictatorial.

**Actionable**: When tempted to explore beyond scope, write: "Found X—worth auditing now, or defer?" and wait for reply.
