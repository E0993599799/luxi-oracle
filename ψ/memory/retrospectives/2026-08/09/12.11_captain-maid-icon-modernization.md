**The mistake**: Assumed `Facebook`, `Instagram`, `Twitter`, `Youtube` would be in lucide-react. They're not — lucide-react doesn't include brand-specific icons (trademark concerns).

**What happened**: Built contact page with these imports → deployment failed 3 times with "not exported" errors. Each failure required:
- Revert imports
- Research available icons
- Update to alternatives (Globe, Camera, AtSign, Video)
- Redeploy

**Why it matters**: ~15 minutes lost to trial-and-error that could have been avoided by a quick `npm list lucide-react && node -e "..."` check first.

**Fix applied**: Switched to generic, universally-available icons. Globe = website, Camera = photo/social, AtSign = handle, Video = video platform.

## Lessons Learned

**Lesson 1: Icon library verification is cheap, deployment failures are expensive**

**Rule**: When picking a specific icon by name (especially for brand-related concepts), verify it exists in the library before writing code that imports it. A 10-second node command beats a 30-second deployment failure + context-switch. **Generalizable**: For any third-party UI library with hundreds of options, spot-check availability before committing code to it.

**Lesson 2: TypeScript compilation ≠ runtime verification**

**Rule**: TypeScript type-checking catches syntax errors but not import resolution errors in JavaScript libraries with dynamic exports. Local `npm run build` catches these instantly. Never skip local build before pushing to production CI/CD. **Generalizable**: Trust but verify — automated CI is not a substitute for local testing when dealing with library imports or external configuration.

**Lesson 3: Component abstraction pays for itself in refactors**

**Rule**: When you find yourself updating the same prop pattern across multiple components (emoji → icon), refactor the shared component (TipCard) to use a union type or generic. This session's TipCard refactor from `emoji: string` → `icon: LucideIcon` took 5 minutes and eliminated 4 maintenance sites. **Generalizable**: Small upfront abstraction cost, large downstream savings on type safety and consistency.

**Lesson 4: Context-compacted sessions need explicit state reads**

**Rule**: When resuming a session after context compaction, don't assume prior decisions. Read `git log` and recent commits to understand *what* was done and *why*. In this session, I inherited "icon updates in progress" but could have understood the full scope faster by reading commit messages. **Generalizable**: Human handoff or AI context boundaries require explicit state communication, not inference from partial context.
