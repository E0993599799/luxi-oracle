## Lessons Learned

**1. Verify Infrastructure Before Proposing** (generalizable)
- **Rule:** Before suggesting you build X, check if X (or something serving X) already exists in the fleet.
- **How to apply:** grep history (24h), check related repos, read config files. Takes 5m, saves 5h.
- **Why:** Duplication creates two points of failure (both codepaths) and splits state (messages in two places).

**2. Ask the Consumer First** (generalizable)
- **Rule:** For any queue/storage design, ask first: "How will the consumer actually read this?" If the answer is "periodically query an endpoint" or "poll Redis," that's the design. Build for that, not for perfect internal architecture.
- **Why:** A beautiful queue that no one knows how to check is just a black hole.

**3. Durable Queues > Ephemeral Storage** (generalizable)
- **Rule:** Vercel `/tmp`, Lambda `/tmp`, Cloud Run `/tmp` are session-local. Use them for working files (parsing, transformation). For messages that persist across requests, use: GitHub (dispatch/issues), Supabase, Redis, or S3.
- **Why:** Serverless restarts between requests. Anything written to `/tmp` dies with the request.
